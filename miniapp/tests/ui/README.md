# 微信开发者工具 UI 质量检测

在 miniapp 目录运行 `npm run test:ui`。需要当前项目的隔离 API/MySQL 容器、已授权的微信开发者工具，以及 iPhone 17 纵向模拟器。执行器锁定 402×874 逻辑屏、SDK 3.17.6、636×1382 PNG，并逐状态核对视口尺寸。在本机 Retina 显示器上，将隔离测试项目窗口切到 macOS 全屏，模拟器选择「自适应」。已实测 iPhone 17 在该窗口下显示约 79%，原始 PNG 为 636×1382。普通窗口下约 75%，原始 PNG 为 604×1312。运行前可用 `simulator_screenshot --optimize=false` 核对原始尺寸。

业务回归仍由 `npm run test` 执行。UI 检测使用同一 test 构建和安全扫描，并与业务回归串行。布局数据来自原生 size 和 offset。检查覆盖选定节点、关键控件矩形和文本，结果是待复核的异常线索。绘制层遮挡、文字截断和键盘交互需要结合截图或真机确认。

## 基准审核

1. 运行 `npm run test:ui:capture`，在报告目录查看候选截图、布局和运行证据。
2. 审核候选图后运行 `npm run test:ui:baseline -- <run-id> <new-version> "<变更原因>"`。此命令只创建新版本，写入候选运行 ID、设备、逐页视口、SHA-256 和更新原因。
3. 默认使用 `core-v1`。新版本可用 `UI_BASELINE=<new-version> npm run test:ui` 显式选择。

比较报告保存在 `tests/reports/ui/`，差异图用洋红色突出变化像素，JSON 中记录差异小块的像素范围。单像素任一通道偏差大于 18 即标记为变化。整图变化超过 0.15% 或单块超过 110 个像素才判为需要视觉复核。基准只遮罩固定设备的状态栏时钟。新增动态区域应以具体像素矩形和原因审核。

视觉差异需要对照 DOM、截图和需求后再定性为真实缺陷、非功能性变化或环境波动。选择器失败和交互失败保留对应工具命令及错误。检测命令只生成证据，不晋升基准或自动改写样式。

## 当前覆盖与判读

- 九个截图状态覆盖首页数据就绪、房源列表有数据、收藏筛选空态、详情无图、预约弹层打开/填表/关闭、详情滚动和返回房源列表。
- `LAYOUT_CANDIDATE` 是尺寸、越界或重叠线索，须结合实际截图确认 UI 缺陷。`VISUAL_DIFFERENCE_REVIEW` 需要判断是否影响功能。`ENVIRONMENT_OR_BASELINE` 和 `ENVIRONMENT_OR_RUNTIME` 保留设备、渲染证据或网络诊断。`AUTOMATOR_OR_INTERACTION` 保留定位、选择器和状态断言证据。
- 本版未验证真实软键盘遮挡、任意绘制层命中测试或整页横向滚动。范围是选定节点的矩形边界。图片加载态、收藏写入状态、游客登录提示、管理员页面暂无视觉基准。相关业务行为继续由各自的业务 E2E 验证。

## 扩展场景

运行 `npm run test:ui:extended` 比较 `extended-v1`。采集候选使用 `npm run test:ui:extended -- --capture`。使用同一个晋升命令审核新版本，基准目录和默认核心命令保持独立。软键盘事件通过独立的 `npm run test:ui:device` 入口验收。该命令复核已有真机证据，缺少设备证据时返回退出码 2 并标记 DEVICE_REQUIRED。 [真机采证步骤](../device/UI-ACCEPTANCE.md)

四个页面分别保存原生视口的 scrollLeft、scrollWidth、页面根矩形和关键控件矩形。图像场景在隔离 API 中临时放置本地 PNG，检查 aspectFill、图框几何和实际渲染像素。收藏用例验证 QA 用户的记录由零变一再恢复为零。管理员场景仅查看与滚动。

管理员视觉基准依赖当前隔离库的 QA 预约数据。预约内容或数量发生合法变化时，应审核差异再决定是否创建新基准。真机键盘高度、滚动及收键恢复的覆盖范围见独立验收报告。
